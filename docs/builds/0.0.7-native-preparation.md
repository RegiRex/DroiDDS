## Implemented behavior

<!-- CodexAstraUlt: Reuse existing compiler/runtime code while removing implicit
inputs and silent omissions from this new reproducible preparation route. -->
The opt-in strict compiler resolver preserves raw header, full decompressed-code
and module bytes alongside the deterministic executable/module collection.
It rejects malformed declared RomFS/CRO/static descriptors, ambiguous/cyclic
paths, unsafe/duplicate names, truncated/overlapping mappings including BSS,
and incomplete compressed streams. Expanded metadata has admission limits
before permissive CRO parsing. Code-less or multiple-code-segment CROs are
explicit unsupported cases, not silently discarded modules. This is bounded
admission, not full cryptographic container-integrity or CRO-semantic verification.

The preparer cross-checks compiler resolution against the runtime filesystem
reader, including raw NCCH/exheader, decompressed code, segment fields and each
selected module's path/bytes. `generate_resolved` consumes that same collection
with `HintPolicy::Disabled`, without reloading the title or searching local or
bundled hints. Legacy compiler entry points retain existing behavior; shared CIA
truncation checks now return errors before unsafe fixed-field indexing.

The coordinator reuses the existing snapshot and process supervisor, validates
exact bounded inventories and raw descriptor consistency, and computes SHA-256
for inputs, components, logical segments and generated files. Timing/process
results stay in a separate run report. A complete manifest is published
atomically without replacing an existing destination. Partial writes, failed
workers, mutation, signals and timeouts cannot qualify preparation.

No new external package or tool is added: the lockfile changes only for the new
workspace package. Normal Android and interpreter diagnostics have no new
compiler or logging dependency. See [the local procedure](../PRIVATE_TITLE_PREPARATION.md)
for bounds, private outputs and the next test.
