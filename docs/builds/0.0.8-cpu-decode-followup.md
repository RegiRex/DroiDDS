## Changes and compatibility

<!-- CodexAstraUlt: Remove repeated representation work while keeping identical
memory reads, draw-error priority and retained native-library compatibility. -->
The CPU input decoder selects one of 16 format/count combinations per field and
uses fixed component widths. It preserves translation, slices, fallback reads,
loader order, fixed/default values, integer conversions and floating-point bits.
It does not assume that translated memory is contiguous across vertices.

The title runtime now checks renderer presence and its existing draw-error
predicate directly. Previously every dispatch cloned the complete hardware
report to inspect only `draw_errors` and `last_error`. The observed intro made
53,649,900 runtime dispatches; that is not an instruction or elapsed-time measure.
Full diagnostics are still retained and exported. Machine, route, draw and native
fence failures keep their existing priority and fail-stop behavior.

Fixed system-call, end-frame and audio-event totals will identify more of the
remaining core work. Each records its nested command-processing time so that
rendering is not counted twice. These natural event boundaries need no
per-instruction clock, growing trace or background monitor. Their remainder is
not a measurement of native execution alone.

Shader arithmetic, output assembly, geometry, drawing, scheduling and admitted
native-code checks remain unchanged. The optional shader JIT stays disabled.
Preparation, both completed 521-object private builds, manifests, imports, saves
and signing identity remain reusable; only the generic player is rebuilt during
packaging. Further Thor GPU tests and audio-perfection work remain deferred.

## Timing fields and host measurements

<!-- CodexAstraUlt: Define coarse timing subsets exactly so the next report
narrows the residual without mislabelling it native CPU or hardware utilization. -->
`runtime.core_work` has fixed `svc`, `frame` and `audio` records. Each contains
`calls`, `wall_nanoseconds` and `nested_command_wall_nanoseconds`. SVC covers
actual CPU-dispatched HLE handling, excluding trace and scheduler bookkeeping.
Frame covers clock updates, renderer boundaries, held GSP work and interrupts,
including optional pacing. Audio includes DSP and peripheral ticks, even when
DSP is inactive. The three scopes do not overlap each other. Their nested
command times are already included in both their wall totals and the existing
command total. Subtract each `(wall - nested_command_wall)` from the existing
`core - command - scanout` residual to obtain a narrower **unclassified** total;
this still includes native/interpreter execution, scheduling, guards and memory
synchronization. Fixed totals are host observations, not guest snapshot state.

<!-- CodexAstraUlt: Keep the authored fetch benchmark's full limitations and
flat fallback result alongside the positive component timings. -->
The release-mode authored input-fetch benchmark compares old/new implementations
in one x86-64 executable, alternating order across four pairs. It exercises full
`InputPlan::fetch` calls, including templates, translation, slices or fallback
reads, with five-field float/mixed inputs. It excludes index expansion/dedup,
plan lookup, shaders and real guest-memory synchronization. Separate correctness checks
compare all output bits and memory-call sequences across all 16 formats. For 320-input
batches, each sample performs **262,080 fetches**:

| Authored input / memory route | Former median | Specialized median |
| --- | ---: | ---: |
| Float / slice | 9.884 ms | 7.238 ms |
| Float / fallback read | 17.700 ms | 15.168 ms |
| Mixed / slice | 7.629 ms | 7.225 ms |
| Mixed / fallback read | 12.113 ms | 12.232 ms |

24- and 1,024-input batches show the same broad pattern. A second completed
measurement also shows float/slice improvement and essentially flat mixed
fallback behavior. This is not a universal speedup or a prediction for Thor.
Logs: `/workspace/droidds-preview5-vertex-benchmark.txt` and
`/workspace/droidds-preview5-vertex-benchmark-repeat.txt`. Neither benchmark
uses private game data or a timing pass threshold.
