# Permission-remap correction toward 0.0.7

<!-- CodexAstraUlt: Record an independently reproduced native-build prerequisite
without attributing Dark Moon's silent prefix to this memory defect. -->
Reviewed 2026-10-28 (America/New_York). The
[private title plan](../PRIVATE_TITLE_BUILD_PLAN.md) identified a fast-pointer
remap concern before general native execution. Original tests now reproduce it:
after an RW mapping is replaced by RX at a different physical page, writes can
still modify the old backing. Removing read access likewise leaves an old read
pointer; releasing a GPU guard can restore a revoked pointer from the stale
underlying table.

## Correction and scope

<!-- CodexAstraUlt: Describe the changed mapping behavior and its limits rather
than treating one fixed permission path as complete native-code protection. -->
For every successfully backed mapped page, `Memory::map` now replaces all four
read/write and CPU fast-table entries from the new permission mask and physical
backing. A missing permission produces a null entry. Existing GPU guards keep
CPU entries null until synchronization; guard release uses the current permitted
pointer. Re-enabling access points to the new backing. Table allocations and the
exported ABI remain unchanged; no per-access logging or extra hot-path branch is
added.

The correction does not change failed physical-backing map semantics, repair
arbitrary overlapping mapping metadata, enforce the execute bit, or implement
native-code invalidation/CRO unload safety. Those remain separate work. Neither
the cloud tests nor the owner-reported private runs establish that this defect
occurs during Dark Moon startup. No DSP, guest predicate or game instruction is
changed.

## Verification

<!-- CodexAstraUlt: Preserve actual before/after reproduction and distinguish
public fixture validation from the private game/device acceptance gates. -->
All five new original regressions failed against the previous `Memory::map`
implementation. They cover revoked writes through all Bus widths and bulk
access, revoked reads, no data permissions, restoration with different backing
through exported native tables, and guarded revoke/restore. After correction,
all 14 selected memory tests pass. Physical old/new backing checks establish
that denied writes do not merely report a fault after altering memory.

Commands executed in this cloud checkout with the existing offline toolchain:

```bash
cargo test --offline --locked -p zakuro-core --lib memory::remap_tests -- --test-threads=1
cargo test --offline --locked -p zakuro-core --lib memory:: -- --test-threads=1
cargo test --offline --locked -p zakuro-core -p droidds-title-tools -- --test-threads=1
cargo test --offline --locked -p droidds-runtime-probe --lib
```

The first command supplied the five failing reproductions, then passed on the
corrected code. The broader suites pass **155 core unit tests, seven core
integration tests, 19 title-tool tests and eight runtime-probe library tests**:
189 distinct tests, without exclusions or ignored tests. Socket tests also pass
in this environment. Zero-test doc suites and repeated focused runs are not
included in that total. A final focused rerun passes after adding a literal
READ-mask case alongside RX and formatting the new code. New-module formatting,
`git diff --check` and relative documentation-link checks pass.

The tests use original data and the existing target directory; no new tools
