## Scope and source

The selected Zakuro revision is `412900a5a020301da15c1cc382585e05a489a535`.
CPU/common remain Git-pinned; core, filesystem and GPU sources needing fixes are
maintained under `vendor/zakuro`, with original hashes and the MIT notice.
The desktop frontend is excluded. The optional CPU PICA Cranelift JIT is disabled
because its unbounded thread-per-miss policy is not qualified for this baseline.
The existing accurate vertex interpreter remains available.

The 3dsrecomp compiler originates at
`c3f21f94ba50d688025febc8974ff348d471b587` and is maintained under
`vendor/3dsrecomp` to correct conditional-flow budget boundaries. The recomp ABI
remains exactly Git-pinned, ABI 4/generation 3. Original attribution is preserved;
DroidDS modifications use adjacent `CodexAstraUlt` comments.

The original `droidds-original-pica-ipc-v1` fixture constructs a decrypted NCCH/CXI
from public formats. Its ARM code connects to `srv:`, obtains `cfg:u` and
`gsp::Gpu`, queries the actual model, copies its own PICA list to VRAM, and submits
two guest draws. A red target with a green quadrant gives an asymmetric 8×8
oracle. Readback uses independent small Morton/address and ABGR decoding.
There is no host replacement draw and no retail-derived input.

Three execution routes are required: interpreter/software, native/software and
native/Vulkan. Each matches 64 pixels. Native execution deliberately reaches a
missing entry and resumes through two outer-interpreter instructions; this is
distinct from the ABI's callback fallback counter. The fixture executes 606 guest
instructions: 604 native plus two interpreted in each native route, or 606 in the
interpreter reference. These are bookkeeping counts, not hardware-cycle accuracy.

## Corrections driven by execution and review

- Conditional backward branches previously charged exit-path instructions on
  each taken iteration: the earlier fixture counted 598 interpreted instructions
  but 1,598 native-path cycles. The compiler now creates a fallthrough block
  boundary. Independent executed ARM/Thumb regressions verify nine-instruction
  loops and sliced-budget resumption. The final fixture has eight additional
  instructions for its asymmetric graphics region and agrees at 606.
- Correct New 3DS header bits, resolve physical regions and commitment limits
  before RAM construction, preserve legacy application caps, and report matching
  configuration/service data. Actual loader tests cover supported layouts and
  explicit unsupported-mode rejection. Heap/linear allocation checks prevent
  crossing or overwriting reserved mappings; failed restore preflights layout
  and quota before changing live RAM.
- Vulkan validation exposed image barriers inside dynamic rendering, invalid
  views on transfer-only images, missing transfer-source usage on readback
  images, and unsynchronized surface clear/upload writes. Fixes retain strict
  validation instead of accepting matching pixels with API errors.
- Renderer admission is bounded at 16 outstanding compilation jobs (including
  uncollected results), 256 translation entries, 8 MiB accounted shader payload,
  512 specialization requests and 512 retained pipelines. Deferred work can
  retry while generic rendering continues; existing in-flight resources are
  preserved. Required qualification rejects unexpected software raster fallback,
  draw/compile errors and resource-limit events.
- Before entering the full runtime, Android atomically preserves completed
  CPU/Vulkan results in the existing report with `status: running`. Process death
  retains useful partial evidence without a new bundle or duplicate writer.

## Qualification limits and next step

The bounded fixture's immutable executable page is checked before and after
each dispatch, and origin mismatch, changed text and a real executable store
are tested. This does not qualify general CRO unloading, executable aliases,
concurrent writers or full scheduler behavior.

Actual Vulkan rasterization and its vertex-shading mode are reported separately.
The inherited policy may use CPU vertex shading on integrated/mobile GPUs.
Static-state generic pipelines can still compile synchronously on first use.
The renderer retains a 256 MiB staging-ring baseline; object/admission limits do
not bound all surfaces, textures or driver allocations, nor prove sustained
memory stability. Those remain explicit optimization/qualification work.

No retail title or Thor 0.0.5 runtime run has occurred in the cloud. The private
control-title baseline and separate Dark Moon, Xenoblade and Sonic results remain
open. Public fixtures can proceed without uploading games. Next: the owner's
0.0.5 report, then visible interactive 3DS homebrew and lifecycle work for 0.0.6.
