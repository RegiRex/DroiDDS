On 2026-10-22 the owner's [paired Dark Moon runs](../host-tests/dark-moon-2026-10-22.md)

measurement exposes early kernel activity without increasing the run's limits.

## Implemented behavior

<!-- CodexAstraUlt: Preserve accurate syscall outcomes and bounded metadata;
the diagnostic observes existing kernel behavior without changing its replies. -->
- Retain the first 64 and latest 128 nonoverlapping scheduler/SVC events, with
  total/omitted counts and bounded syscall counters. No per-frame or idle-step
  event stream is written.
- Record actual interpreter SVC PCs, caller IDs, six scalar argument registers
  and four returned registers. Pending/exited/faulted calls have no fabricated
  immediate return. A resumed wait records the actual registers after scheduler
  handling and verifies the thread incarnation.
- Capture final thread status, wake deadlines and wait-object metadata for up
  to 64 threads and eight objects per thread; pending-call correlation is also
  capped at 64, with explicit dropped/truncated accounting.
- Default tracing is off. Normal frontends do not allocate trace storage.
  No new dependencies, guest-memory reads, guest strings, instruction dumps,
  images or audio are added by the trace. Save/restore during tracing is outside
  this fresh-process diagnostic's supported scope; save-state format is unchanged.
- Validate activation, schema, capacities, scalar types and retention accounting
  in the Python coordinator. The runtime gate now requires an actual worker
  trace-on/off integration case in addition to the existing original-container
  and malformed-input controls.

The core's `services_seen` list reflects `srv:GetServiceHandle`, so an empty list
does not exclude earlier syscalls or service-manager initialization. A returned
r0 is not always an error code: some syscalls return data. No syscall, scheduling
or rendering semantic fix is included in this measurement change. No new APK or
release tag is produced, and no private game is executed in this cloud session.
