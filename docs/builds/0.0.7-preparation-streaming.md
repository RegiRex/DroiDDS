## Correction

<!-- CodexAstraUlt: Separate source-generation efficiency from eventual native
compiler resource use and handheld performance; both remain distinct gates. -->
The compiler now offers a fallible file consumer. It releases completed source
chunks instead of retaining the entire generated C collection. The preparer
admits each file before writing, with one aggregate ceiling covering raw identity
components, C/headers and the success JSON descriptor. The coordinator independently
checks the same inventory. Legacy collecting callers remain supported, and the
standard build writer also streams. File contents, numeric source names, compile
order, entry/origin tables, interpreter fallback and ABI 4/generation 3 remain
unchanged. A rejected consumer stops later output and suppresses the success event.

The discovery-only lowering pass no longer runs the local-register dataflow pass
whose output it discarded. Final generation still runs that analysis. Shared
headers were already deduplicated; the measured byte count alone does not justify
omitting code, tables or modules to fit an arbitrary limit.

`--prepared-mib` defaults to 512 and accepts 1–1024. The measured private result
justifies one explicit 1024 MiB retry. The coordinator reserves the snapshot,
selected allowance and a separate 64 KiB failure-diagnostic allowance before
launch. CPU/wall/address-space defaults remain 260 seconds/130 seconds/4096 MiB.
Success metadata has the coordinator's 1 MiB ceiling; components/C files retain
64 MiB per-file admission. There are at most 4096 generated artifacts and 8192
total successful files; directories are not counted as files.

An ordinary rejection after output creation attempts to retain
`prepare-failure.json`: stage, accepted file/byte counts, limit and attempted
next-file/aggregate sizes. Counts cover fully written/synced files only. I/O failure
can leave a partial file; a kill or panic need not produce this diagnostic.
Only a normal worker exit 2 can attach its strictly bounded diagnostic to the
coordinator report, and failure never publishes a manifest.

Streaming still retains discovery results, individual function/chunk buffers and
origin tables. This is not a bound on whole-worker memory or an OS disk quota.
The process memory limit remains independent. No APK-size, native-speed or Thor
memory improvement is claimed from a host source-generation correction.
