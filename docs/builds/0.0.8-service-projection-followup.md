## Changes and compatibility

<!-- CodexAstraUlt: Remove the completed-register intermediate only on the
ordinary CPU vertex route; preserve arithmetic, masks, geometry and lane order. -->
The ordinary CPU vertex route now projects completed SIMD output components
directly into the rasterizer's 21-component vertex representation. The existing
output-mask/semantic plan supplies fixed selectors; each selected component is
transposed once per completed lane group instead of reconstructing a full
register row for every lane and then mapping that row.

The eight-lane output intermediate shrinks from **2,048 bytes to 672 bytes**
(`8 × 16 × 4 × sizeof(f32)` versus `8 × 21 × sizeof(f32)`). This is a compact
temporary output buffer, not a reduction in the full shader execution state,
divergence/fork storage, draw buffers or process memory. Internal shader state
and fork copies remain. Arithmetic, instruction execution, parallel thresholds,
worker chunking, input order and draw count retain their existing behavior.

Selected components retain their exact bits, including signed zero and NaN
payloads. Constant defaults and unwritten fields reset for every batch. Completed
fork/final overwrite order, partial batches and repeated semantic selectors are
preserved. Geometry retains its full-register route. Shader tracing and optional
JIT builds use the existing full-output fallback; the optional shader JIT stays
disabled in the supported candidate configuration.

Preparation, generated-title ABI, both completed 521-object private
builds/libraries, imports, saves and owner signing identity remain reusable.
Repackaging rebuilds the generic player rather than the title objects. Further
Thor GPU tests and audio-perfection work remain deferred.

## Fixed diagnostic attribution

<!-- CodexAstraUlt: Define fixed parent/child timers and cache counts precisely;
these bounded report fields do not create a per-instruction or growing history. -->
The existing `runtime.core_work.svc`, `frame` and `audio` scopes retain their
`calls`, `wall_nanoseconds` and `nested_command_wall_nanoseconds` fields. The
candidate adds fixed attribution tables and exports only observed entries:

| Report field | Fixed storage and meaning |
| --- | --- |
| `svc_by_number` | 129 slots: numbers 0–127 plus one overflow row with `number: null`; reuses the aggregate SVC measurement. |
| `ipc_by_service` | 20 canonical service families; aliases share a family and unclassified names use `other`. |
| `gsp_direct` | 10 fixed operation categories for direct GSP requests, including queue-dispatch wrappers. |
| `gsp_queued` | 10 fixed operation categories for consumed queued GX commands. |

Each observed row has the same three timing fields as its parent. The numbered
SVC rows partition the aggregate SVC total before counter saturation. IPC service
timers, direct GSP timers and queued GSP timers are **nested children**, not extra
disjoint work. A queue-dispatch request includes its queued children; queued work
can instead execute later during frame refresh. Do not add these tables together
or add them to core/PICA totals. Their nested PICA subsets already appear in both
the child wall totals and the global command-list timer. A service total does
not account for all SVC handling.

Direct and queued GSP categories distinguish DMA, command lists, memory fill,
display transfer, texture copy, cache maintenance, queue dispatch, register I/O,
buffer swap and other operations. The wrappers preserve request results, early
returns, interrupt ordering and deferred execution. Calls use fixed accumulator
storage without per-call allocation or retained request words, guest names,
addresses or growing traces. Natural IPC/GSP boundaries add clock reads; their
cost still requires integrated/device evaluation and is not assumed to be free.

`runtime.gpu.hardware.retained_surfaces` records the surface cache's entry count
at report time using its existing length. It does not count bytes, active/dirty
surfaces or leaks. Invalidation can retain cache allocations, so a positive or
increasing entry count alone does not establish a memory leak. The inexpensive
per-dispatch draw-error guard remains unchanged; reporting does not cause a
renderer failure or a full snapshot on every dispatch.

## Authored host benchmark

<!-- CodexAstraUlt: Report the complete paired host scope and medians without
promoting component timing to a promised handheld or end-to-end speed gain. -->
The release-mode projection benchmark compares the previous register-row route
and the new projection route in one x86-64 executable. It includes shader
execution, output allocation/mapping and unchanged worker thresholds, using a
two-thread pool. Three authored shaders (short, arithmetic-heavy and divergent),
two output masks (`0` and `0xA5`) and five input counts (8, 64, 320, 512 and 4,096)
produce **30 cases**. Each case checks both routes against scalar output bits,
then runs **five alternating-order pairs**, each processing at least 65,536 inputs.

Across these 30 case medians, the new route used **3.5–32.5% less elapsed time per
input**. The table shows all six 320-input cases, including the largest observed
median reduction. The smallest reduction was the arithmetic shader, mask 0,
512 inputs: 136.710 to 131.875 ns/input (3.54%).

| Authored shader / mask, 320 inputs | Former median | Projected median | Reduction |
| --- | ---: | ---: | ---: |
| Short / `0` | 59.308 ns/input | 40.024 ns/input | 32.52% |
| Short / `0xA5` | 60.101 ns/input | 44.898 ns/input | 25.30% |
| Arithmetic / `0` | 178.782 ns/input | 161.101 ns/input | 9.89% |
| Arithmetic / `0xA5` | 176.145 ns/input | 158.731 ns/input | 9.89% |
| Divergent / `0` | 107.681 ns/input | 94.184 ns/input | 12.53% |
| Divergent / `0xA5` | 112.518 ns/input | 92.794 ns/input | 17.53% |

Log: `/tmp/droidds-008p6-projection-benchmark.err`; its paired test output is
`/tmp/droidds-008p6-projection-benchmark.out`. These are authored host inputs,
not Dark Moon shaders. The measurement excludes input fetching, clipping,
placement, Vulkan draw/transfer work and the new IPC/GSP timing overhead. It has
no speed pass threshold and does not predict Android or complete-game performance.
