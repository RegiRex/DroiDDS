  from the Android runtime; host source generation remains a separate command.
- ARM64/Bionic libraries for all four original fixtures, the Rust probe and a
  narrow original JNI bridge.
- Minimal platform Android app, API 29 minimum/API 35 target, package
  `org.droidds.probe`, version 0.0.2/code 2. One background worker runs the fixtures
  and atomically replaces one private report; it has no network permission.
- Reproducible local APK builder, separate persistent debug signing identity,
  static ELF/APK checks and source-input fingerprints.
- Local ADB runner with an explicit device serial, package validation, installed
  APK hash verification, per-run nonce and bounded completion deadline.

lambda bootstrap signatures require the Java 8 compilation platform before D8,

was bypassed. The final local output is `out/android-probe-final-0001/`; intermediate
attempts retain failed status and are not passing evidence.

## Reproduce and continue

Follow [Android probe instructions](../ANDROID_PROBE.md). Full regression command:

```bash
python3 tools/build_foundation.py --output out/foundation-android-new --jobs 2
python3 tools/build_android_probe.py --sdk "$ANDROID_HOME" --java-home "$JAVA_HOME" \
  --output out/android-probe-new --jobs 2
```

Toolchain: Rust/Cargo 1.95.0, JDK 17.0.20.1, Android SDK 35/build tools 35.0.0,
NDK 27.3.13750724, Python 3.12.14 and host GCC 14.2.0. This incremental build uses
valid retained outputs and is not a clean-build timing benchmark.

The next device task is the short automatic Thor CPU probe. The owner does not
need to test the Linux build manually. A passing Thor result only establishes
the observed device's loader/CPU-fixture behavior and page size. Full A0 still
requires Vulkan capability/pipeline drawing and remaining platform qualification;
M1's broader semantics/module-lifetime gates also remain open. No Dark Moon or
general game-performance result is claimed.
