## Concrete allocation removal

<!-- CodexAstraUlt: Remove a structurally unnecessary per-draw allocation while
retaining topology, winding, draw count and visible output as correctness gates. -->
`raster.rs::assemble` previously built a complete vector of triangle tuples that
`rasterize` consumes once. The candidate replaces this intermediate allocation
with a lazy iterator and an exact triangle count. List, strip and fan topology,
strip winding, indexed ordering and degenerate-count behavior must remain the
same. No draw is skipped, and no additional retained-memory pool is introduced.
A removed allocation is a concrete structural improvement; its Thor speed
benefit is unmeasured.

This path executes when CPU vertex processing feeds placed vertices to Vulkan,
including the Thor's previously selected path; it is not limited to software
rasterization. The GPU vertex path can return before this assembly step.

## Controlled vertex comparison

<!-- CodexAstraUlt: Select the renderer path per session before startup, rather
than mutating process-wide settings or treating selected policy as actual work. -->
The candidate adds an explicit **Automatic / CPU / GPU** vertex-shader choice.
Automatic preserves the existing device-selection behavior. A choice applies
before renderer startup and remains fixed for the session. The Native/Interpreter
guest CPU setting is separate; selecting GPU vertex work does not move guest
ARM execution to the GPU or eliminate CPU fallbacks.

The shared runtime, C/JNI boundary and Android frontend carry this choice without
changing the compiled game's ABI. Existing title preparation and all 521 Android
objects remain reusable. Reports must distinguish requested policy, selected
renderer behavior and actual path evidence; a selected GPU flag alone cannot
prove that every draw used GPU vertex shaders.

Command processing includes decoding, shading, recording and waits. The 57.6%
summary does not justify assuming GPU vertex execution is faster, and the
remaining core and frontend time must remain visible. This candidate does not
enable the optional CPU shader JIT or add continuous logs or monitoring threads.

<!-- CodexAstraUlt: Describe actual bounded measurements instead of equating a
requested GPU setting or submitted references with shader invocations. -->
`gpu.vertex_processing` adds lifetime `cpu_batches`, `cpu_vertex_inputs` and
`cpu_wall_nanoseconds`. Two clock reads surround each actual CPU processing
batch, including vertex/geometry processing, packing and worker joins. Array
decoding, clipping and Vulkan submission are outside this timer. Indexed inputs
are counted after deduplication. Already transformed fallback vertices do not
count a second batch, and cache invalidation does not erase lifetime totals.

Hardware diagnostics record `gpu_vertex_draws` and `placed_vertex_draws` at actual
Vulkan draw recording, plus `dynamic_blend` and `dynamic_logic_op`. Placed draws
use already transformed vertices and do not identify how many CPU shader calls
produced them. These fixed fields add no event history or sampler thread.

## Device comparison boundary

<!-- CodexAstraUlt: A private per-title package cannot load another title's
fixture, and an unrelated public signing certificate cannot update it. -->

for the private device comparison. The bounded Thor comparison is itself the
first qualification of this explicit choice on that device. No separate public
diagnostic installation is required. The private app cannot import the unrelated

preparation, completed ARM64 library and owner key; repackage only with a version
code above the installed one and at least 12. Compare the same bounded Native
menu route at the same resolution and settings with CPU and GPU vertex selection,
at most 120 wall seconds per run. Stop the GPU trial at the first new failure or
visual corruption. Export and label each report **immediately after stopping and
before any restart**. Preserve remaining saves, imports, all prior reports and
both compiled target builds. Report requested policy, selected/actual path evidence
and phase timings separately. Audible quality needs an actual listening observation;
if unavailable, mark it unobserved instead of inferring it from counters. A test
deliberately changing shader location is an experiment, not a promised speed fix.
