## Changes and verification

<!-- CodexAstraUlt: Make each validation layer and its evidence distinguishable
from a complete machine-equivalence, native-plugin-sandbox or device claim. -->
- `private_runtime_inputs.py` consumes retained canonical manifests, recipes,
  source snapshots, objects and receipts under a shared compilation lock. It
  validates recorded compiler provenance without running the compiler.
- `private_runtime_elf.py` validates the full relocated entry/module/origin graph,
  code pointers, original instruction-piece hashes, mutable-control storage,
  table ownership, initial values and finite parsing bounds. The actual audited
  mmap is SHA-256 hashed. No library is loaded by this stage.
- `run_compiled_title.py` seals exact admitted library/identity bytes in Linux
  memory descriptors. `droidds-native-title` independently compares runtime-loaded
  title components and mapped bytes against those sealed identities before
  loading the native library. Old compilation manifests remain unchanged.
- The opt-in base-code fence relocates FCRAM into owned page-aligned backing,
  rebases all four memory tables, protects the executable's text and verifies
  mappings before dispatch. Default frontends retain heap-backed memory. State
  restore rejects while fenced. Dynamic modules remain interpreted, and missing
  entries retain interpreter fallback. Protected writes fail-stop the isolated
  worker rather than continuing with stale code.
- The process supervisor requires sealed input descriptors, limits wall/CPU/
  address-space/file/log resources and cleans up descendants. Signals have no
  invented cause. Reports distinguish attempted load/execution from completion.
- Strictly typed checkpoint/final reports prevent empty or falsely aligned states
  from matching. Comparisons require equal guest-cycle checkpoints or guest-exit
  cycles. Callback-interpreted instructions are subtracted from the compiled
  dispatch total before qualifying actual generated native work.

The six historical compilation-contract Python files are unchanged. Cargo adds
one host worker package and the core's edge to the already locked `libc` package;
no external dependency version changes or generated-code ABI changes occur.

## Remaining scope

<!-- CodexAstraUlt: A bounded diagnostic is deliberately narrower than shipping
general native mutable modules or claiming sustained game playability. -->
This host-only path supports Linux 4 KiB pages and immutable main-executable
native code. It does not implement transparent deoptimization, native CRO
execution under this policy, or Android packaging. SHA-256 identities bind inputs;
state comparisons use noncryptographic FNV fingerprints and selected scheduler
state, not every thread/HLE object. Ordinary CRT constructors remain trusted.
No private game execution, interactive boot, Thor performance, or Dark Moon
graphics/audio correction follows from these original-fixture results.
