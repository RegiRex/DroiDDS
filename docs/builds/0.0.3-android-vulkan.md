## Reproduce

<!-- CodexAstraUlt: Use portable toolchain inputs and an actual host driver;
retain explicit validation and separate Android runtime qualification. -->

Follow [the Android instructions](../ANDROID_PROBE.md) for toolchain installation,
Vulkan driver/layer discovery, signing behavior and the device test.

```bash
python3 tools/build_foundation.py --output out/foundation-new --jobs 2
python3 -m unittest discover -s tools/tests -v
VK_LAYER_ENABLES=VK_VALIDATION_FEATURE_ENABLE_SYNCHRONIZATION_VALIDATION_EXT \
python3 tools/build_vulkan_probe.py \
  --ndk "$ANDROID_HOME/ndk/27.3.13750724" \
  --vulkan-library "$VULKAN_LOADER" \
  --output out/vulkan-new --require-validation
python3 tools/build_android_probe.py \
  --sdk "$ANDROID_HOME" --java-home "$JAVA_HOME" \
  --output out/android-new --jobs 2 --prerelease
```

Toolchains used: Rust 1.95.0, JDK 17, Android platform/build tools 35/35.0.0,
NDK 27.3.13750724 and host GCC 14.2.0. Host execution used Mesa 25.0.7 and
Vulkan loader/Khronos layer 1.4.309. The tag workflow repeats foundation, APK,
host Vulkan and bundle gates using the GitHub runner's software driver.

This bounded offscreen fixture does not qualify PICA translation, surface
presentation, game correctness, sustained memory behavior or handheld speed.
Three successful resource cycles are not proof of leak freedom. The next owner
test runs 0.0.3 on the Thor and saves the combined JSON with **Save report**.
