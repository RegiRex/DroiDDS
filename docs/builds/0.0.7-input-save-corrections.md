## Input sampling

<!-- CodexAstraUlt: Preserve guest input timing across variable host slicing;
wall-clock yields must not consume an entire queued tap before guest polling. -->
The generic player previously dequeued an input state and published a HID sample
on every cooperative slice. A slow frame could require several slices, advancing
the shared HID ring and publishing a queued release before the guest polled its
press. Repeated publication also erased additions/removals and signaled extra
input events according to host scheduling rather than guest frame progression.

The runtime now latches one input state per guest frame. The Android queue keeps
the subsequent transition until that frame completes. Initial HID resource
creation receives its first real sample immediately; ordinary frame boundaries
wait for the next supplied input. Explicit pause still releases controls at once
and starts a fresh sampling interval on resume. No core frame scheduler change,
per-frame log or fabricated frame is introduced.

An Android joystick event also now submits its hat directions and both sticks
atomically. A diagonal reversal previously queued intermediate opposing
directions and several separate states; frame-based retention would spread
those states across frames. Duplicate source ownership of an unchanged held
button no longer adds redundant queue entries.

Original guest tests execute real GetIPCHandles and guest polling in native and
interpreter modes, check ring stability through repeated yields, and observe
press/touch consumption followed by release. A negative control reapplies the
old per-slice publication and reproduces the missed press. Java queue tests cover
the matching frontend behavior. This is functional timing coverage, not a Thor
latency or performance measurement.

All **23 title-runtime tests** pass, including the three new HID cases and four
new save cases below. All **67 Java checks**, runtime formatting and strict
Clippy pass. Independent input/lifecycle review passes. Core frame-boundary
dispatch granularity is unchanged; this is not exact hardware HID timing or a
guarantee about every game's polling schedule.

## Save files

<!-- CodexAstraUlt: Return meaningful guest failures and preserve handle rights;
an operating-system write attempt is not automatically a successful game save. -->
Original ARM guests reproduce successful replies for writes through read-only
handles and for failed host writes. The correction preserves read/write rights,
returns actual I/O failures, and distinguishes legitimate EOF from an error.
File synchronization follows explicit flush requests, write-flush flags, dirty
file close and the selected archive's commit. Commit does not recursively scan
an archive or synchronize unrelated files. Ordinary writes do not force a sync
on every chunk. Metadata operations synchronize only the paths they touch.

Dirty state is retained after failed mutation/synchronization. A failed close
keeps the file available for retry. Linked file sessions retain independent
entries so closing one does not invalidate its sibling. New serialized host-file
records preserve access and dirty state; legacy records without access metadata
reopen read-only. This affects old emulator snapshots, not the contents of the
owner's save files. It does not implement transactional or power-loss-atomic 3DS
save archives.

The authored guest uses real FS IPC to format its isolated archive, create/open
and write a file, flush/commit/close it, then read it from a fresh runtime session.
Separate controls exercise denied modes, failed backing-file operations and
linked handles. Host fault injection changes only test-owned files after the
guest has opened them. No private game or user save is used by these checks.

The full core suite passes **181 unit tests and seven loader integration tests**,
including five new focused save controls. The **11 native-worker, eight retained
runtime-probe and five player tests** also pass. Independent filesystem review
corrected write-only host-file flushing and relative archive-directory handling
before final validation. Snapshot controls preserve old postcard variant IDs,
check conservative legacy access, and cover current access/dirty round trips.
