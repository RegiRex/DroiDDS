## Change

<!-- CodexAstraUlt: Retain established defaults while allowing an explicit,
bounded CPU allowance without changing emulated execution or failure classification. -->
`tools/run_private_title.py` accepts parent-only `--cpu-seconds`, integer range
1–311. The maximum is the largest CPU cap already possible under the old
310-second maximum wall deadline. Omitting the flag preserves the exact previous
`ceil(timeout)+1` default. Both CPU soft and hard limits receive the selected
value; wall timeout, process-group cleanup and all other caps are unchanged.

The coordinator records resolved `requested.cpu_seconds` and launch limits in
`process.cpu_limit`, scoped to all threads of each process. It does not measure
CPU usage or claim a combined process-tree allowance. SIGKILL remains
`worker_failed / worker_signal_9`, and a prewritten or partial worker report
cannot turn a failed process into accepted execution evidence.

The option is not forwarded to the Rust worker. Guest settings, strict behavior,
worker schema and renderer/audio implementation are unchanged. The next private
task explicitly requests 260 CPU seconds while retaining its 120-second worker
wall budget and 130-second external deadline. This is a documented CPU increase,
not a promise that the run will complete or a relaxation of its other limits.
