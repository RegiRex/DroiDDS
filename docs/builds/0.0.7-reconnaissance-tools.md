## Implemented behavior

<!-- CodexAstraUlt: Reuse the selected loader/runtime and add a narrow diagnostic
path before native packaging obscures a title's first unsupported operation. -->

- `droidds-title-tools` provides a Linux host worker using the existing NCCH/NCSD/CIA
  loader, interpreter, HLE services and software renderer. It records resolved
  metadata, guest-region accounting, counters and the first observed blocker.
- Optional core diagnostics stop on undefined instructions and breakpoints,
  preserving the failing PC. Existing frontends retain their default behavior.
  The worker checks unsupported SVC/service, memory/prefetch and fatal-error
  records after each full dispatch. Implemented HLE paths may still be incomplete.
- The Python coordinator makes a streamed, read-only input copy in a fresh private
  directory outside Git; records input/worker hashes and source context; checks
  for mutation; and enforces external process time/address-space limits. Logs and
  reports are bounded. Existing saves and runtime directories are not reused.
- The required host-runtime build gate now tests and builds the worker, and runs
  the coordinator with an original public fixture. No private game enters CI.

No new third-party dependency was added. The host tool has its own version 0.0.1;
Android retains version 0.0.6/code7. No private input, generated title library,
APK or device run is part of this change. No new APK tag is created for this
preparatory tool slice.
