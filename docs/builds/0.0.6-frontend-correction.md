# DroidDS 0.0.6 frontend correction

<!-- CodexAstraUlt: Bind this correction to observed Android problems while
retaining the separate original release and its unchanged native execution. -->

The [first 0.0.6 Thor report](../device-tests/0.0.6-thor-homebrew.md) passes all
automatic checks. The owner confirms that both guest images were visible on
the top physical display. The separate Thor lower display was unused, as
expected for this version's single-display frontend.

The report records 197 audio underruns over 71.467 foreground seconds. Its
generated PCM represents about 70.432 seconds. The original frontend scheduled
each frame relative to its actual wake time, accumulating scheduler delay, and
started AudioTrack before feeding PCM. The correction addresses both mechanisms;
only a new Thor result can determine their effect on actual audio continuity.

The uploaded report's four Android touch callbacks do not establish a valid
touch inside the guest image: outside-letterbox callbacks and releases share
that counter. Guest-observed touch remains zero. New counters distinguish
in-image held callbacks and submitted touch frames; guest consumption remains
the required downstream evidence. The owner's interaction observation is
retained separately without rewriting the raw report.

## Corrective scope

<!-- CodexAstraUlt: Describe the Android changes without claiming a new game
milestone, physical dual-display support or skipped guest work. -->

- Accumulated monotonic frame deadlines, with bounded recovery from overload
  and measured timing delays. Every guest frame still executes.
- Real guest PCM prebuffering before playback on start/resume; bounded queues,
  rate conversion and existing drop/underrun measurements remain.
- Labeled guest displays, clearer in-image touch instructions and controls
  beside the views in landscape.
- A **Recreate view** action to exercise Activity replacement directly.
- Additional bounded diagnostics and strict report consistency checks.

No native CPU, guest fixture, HLE, DSP, PICA or Vulkan implementation is changed.
The same twelve native libraries remain required. The app is **0.0.6 · correction
2**, Android install code **7**, with tag **v0.0.6-probe.2**. Install codes increase
independently of roadmap milestones; this does not advance to 0.0.7.

## Focused Thor gate

Run the automatic probe, then **Test original homebrew**. Both guest images
should be on the Thor's top physical screen. Use D-pad/A, hold and drag inside
the colored lower guest image, then release. Listen for interruptions. Tap
**Recreate view**, briefly switch apps and return, and check controls/audio
again. Confirm the two observation checkboxes when correct. Finish with
**Stop and save session**, then **Save report**.

Require measured guest touch, recovered views/audio after recreation and
backgrounding, normal close and review of the new pacing/audio counters before
promoting the interactive milestone. Public signing remains disposable; preserve
needed reports before manually resolving a DroidDS Probe signing conflict.
