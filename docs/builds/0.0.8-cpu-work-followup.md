## CPU vertex output changes

<!-- CodexAstraUlt: Remove repeated representation work while preserving shader
math, geometry outputs, lane completion order and output-default semantics. -->
`VertexOutputPlan` composes the output-register mask and semantic map once per
ordinary draw. Each vertex then reads its position, color and other varyings
directly from the shader output. Previously this path rebuilt and cleared a full
packed register array for every vertex. The immutable plan is shared across
worker chunks. Geometry keeps the full packed-output path; shader execution,
vertex order, missing-semantic defaults, NaN payloads and signed zero retain
their existing semantics.

The SIMD shader batch now reads its final completed lanes directly from the
batch output instead of copying the entire **2 KiB** output into the fork vector.
Divergent completed lanes still retain their required copies and are consumed
in the same order, followed by the final lanes. Partial batches and unwritten
components remain covered. A test-only copy of the prior behavior supports a
paired benchmark; it is not compiled into the application.

These changes retain the existing parallel threshold and shader semantics. They
do not skip draws, enable the optional shader JIT, replace Vulkan rasterization
or change the generated-title ABI. The code 13 bounded packed-output scratch
remains; this follow-up does not claim that every register copy or allocation
has disappeared.

## Bounded CPU cost reporting

<!-- CodexAstraUlt: Split existing command costs with fixed totals rather than
adding per-vertex clocks, event histories or a second log writer. -->
`runtime.gpu.vertex_processing` retains the existing CPU shader batch/input/time
fields and adds:

| Fields | Scope |
| --- | --- |
| `cpu_geometry_batches` | CPU batches selecting geometry mode; not a count of completed geometry invocations |
| `cpu_parallel_vertex_batches` | CPU batches meeting the vertex-shader input threshold; not geometry-stage parallel work or a count of active workers |
| `input_decode_batches`, `input_decode_wall_nanoseconds` | CPU index expansion/deduplication and attribute decoding, plus immediate-attribute mapping |
| `placement_batches`, `placement_wall_nanoseconds` | CPU triangle assembly, clipping, culling and screen placement before the Vulkan draw |

Shader, decode and placement timers cover disjoint work. All are command-processing
subsets, not extra time to add to command or core totals. Decode excludes the
initial raw index-buffer read and cached input-plan lookup. The new timers exclude
Vulkan work. Placement also counts already-shaded/software fallback attempts;
those attempts do not repeat the CPU shader batch count. Threshold/geometry
counters distinguish path selection without claiming a complete workload profile.
The fields are fixed lifetime totals; there is no per-vertex timing, growing
history, monitor thread or duplicate logging.

## Native code-fence verification cache

<!-- CodexAstraUlt: Avoid whole-text verification after unrelated GPU guards;
retain conservative mapping checks and the actual immutable-code protections. -->
The implemented guard-only invalidation now keeps the verified native-code epoch
when a read/write guard changes virtual pages outside admitted TEXT. Guards
overlapping admitted TEXT still invalidate verification, with empty and saturating
range behavior matching guard installation. Removing a guard checks the **entire
removed range**, including merged guards, before invoking a callback; checking
only the triggering access would miss a larger restoration touching TEXT.

Actual map/unmap operations still invalidate conservatively, including mappings
changed by callbacks. Every native-fence check still verifies the physical backing
identity and fenced mapping. Host `mprotect`, physical-alias protection and
code-write rejection remain unchanged. This removes unnecessary full-TEXT page
scans after unrelated framebuffer guards without weakening admitted code checks.
No code hashing or new per-instruction instrumentation is introduced.

Implementation, independent source review and the five new core controls **pass**.
They cover unrelated guards/aliases and conservative
mapping invalidation, exact range boundaries, merged-range restoration before
callbacks, callbacks remapping TEXT, and an authored 16 MiB cached-versus-forced
revalidation control. The last test validates epochs and prints bounded timings;
timing is not a pass threshold or a handheld speed claim. All 13 fence controls,
including actual subprocess write rejection through native/physical aliases,
pass within the complete core suite.

## Paired host component measurements

<!-- CodexAstraUlt: Report the actual authored x86-64 benchmark samples without

Two opt-in release-mode benchmarks ran on the cloud **x86-64** host. They compare
old/new behavior in one binary and alternate order. The authored workloads contain
no private game data. Timing is descriptive component evidence, not a correctness
gate or a prediction of Thor performance; shared host load is uncontrolled.

`raster::tests::benchmark_vertex_output_plan_against_packing` includes one output
plan per 320-input draw and measures **655,360 mapped vertices per route per
round**. The observed paired times were:

| Round | Previous packing | Planned mapping |
| --- | ---: | ---: |
| 0 | 15.707 ms | 12.090 ms |
| 1 | 19.675 ms | 11.695 ms |
| 2 | 25.583 ms | 20.139 ms |
| 3 | 19.484 ms | 15.953 ms |

`shader::tests::mapped_vertex_batch_speed` compares the copied final batch with
the borrowed final batch using identical allocation, uniforms, projection and
dispatch. Both routes are checked against scalar output before timing. Five
samples per route cover short, arithmetic-heavy and divergent shaders at 8, 64,
320, 512 and 4,096 inputs. For the **320-input** workload, median nanoseconds per
input were:

| Authored shader | Copied final batch | Borrowed final batch |
| --- | ---: | ---: |
| Short | 48.485 | 40.340 |
| Arithmetic-heavy | 164.544 | 157.171 |
| Divergent | 102.117 | 94.465 |

The logs are `/tmp/droidds-008p4-map-benchmark.log` and
`/tmp/droidds-008p4-batch-benchmark.log`. Each reports its single requested
benchmark passed. These results isolate output mapping and batch work; they
exclude the remaining emulator/rendering workload and do not justify adding the
two component improvements together. New ARM64/Thor measurements remain needed.

The release-mode 16 MiB native-text control performs 16 unrelated guard/verify

takes **0.611–5.498 µs**. Epoch assertions confirm 16 invalidations versus zero.
This isolates eliminated full-text scans on the cloud host; the private report
does not measure their former frequency or predict an end-to-end Thor gain.
The bounded control is an ordinary correctness test with descriptive timing;
its log is `/tmp/droidds-008p4-fence-release.log`.
