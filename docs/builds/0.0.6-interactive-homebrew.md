## Original guest and runtime boundary

<!-- CodexAstraUlt: Describe guest-owned images/input/audio and reused services
so an Android demonstration cannot be mistaken for 3DS program execution. -->

The new fixture is **`droidds-original-homebrew-v1`**, an original NCCH/CXI ARM
program built into **`libdroidds_fixture_homebrew.so`** by the existing host
compiler and target C toolchain. The guest uses actual SVC/service IPC to obtain:

| Service | Original guest work |
| --- | --- |
| `hid:USER` | Map and read the runtime's input state; use D-pad/A and touch in the guest's next image/tone state |
| `gsp::Gpu` | Submit PICA commands, display transfers and framebuffer swaps for 400×240 top and 320×240 bottom output |
| `dsp::DSP` | Initialize the HLE pipe, read/convert shared addresses and supply original PCM16 data to the mixer |

The guest creates its own simple image markers and square-wave sample data.
Holding A changes the guest's tone rate. An intentionally unrecompiled helper
retains interpreter fallback. No retail input, derived retail code, direct-host
replacement draw or Android-generated replacement tone is part of the fixture.
The original 0.0.5 NCCH remains a separate required regression.

The selected Zakuro loader/HLE/PICA and vendored 3dsrecomp compiler retain their
existing provenance and shared ABI. This change adds original guest/integration
code and a platform-only Android frontend; it does not import another emulator
or Zakuro's desktop frontend. Read [source boundaries](../UPSTREAM_INTEGRATION.md).

## Automatic contract

<!-- CodexAstraUlt: Preserve the exact automatic contract and its final executed
host proof separately from Android presentation and manual-device observations. -->

The `interactive_probe` report requires three routes:
`interpreter_software`, `native_software` and `native_vulkan`. Each runs four
original input stages: idle; A + right + up; touch at (247, 181); and release.
Independent expected output checks cover all **400×240 and 320×240 pixels** and
stable guest PCM. Route comparisons must agree, with real consumed-input,
service/native/interpreter and Vulkan submission evidence. Vulkan rasterization
and GPU vertex execution remain separate choices; the Thor may retain its
qualified CPU vertex path.

The automatic lifecycle check pauses the runtime, rejects stepping while paused,
confirms no progress, resumes it and requests actual guest exit with Select +
Start. Controls reject an intentionally changed pixel, changed audio sample and
insufficient dispatch budget; changed executable text must be rejected before
CPU progress, and a recreated session must start clean. These checks
cannot demonstrate that a person saw the screen or heard the tone.

Every 0.0.5 regression remains required: the eight CPU fixtures and their
controls; Vulkan platform/capability checks; actual 8×8 runtime fixture; runtime
code guards and Old/New memory layouts; source-bound host GPU tests in normal
and forced-static modes with validation. The APK inventory expands to exactly
**twelve ARM64 libraries** by adding the generated homebrew library, retaining
all existing runtime/JNI and fixture libraries.

## Android presentation, input and audio

<!-- CodexAstraUlt: State the initial readback/presentation compromise and rate
conversion explicitly, without treating them as a retail-performance solution. -->

The frontend stacks the **400×240 top view and 320×240 bottom view on one Android
display**. It presents actual guest readbacks using Bitmap/Canvas. The guest
PICA renderer still rasterizes with Vulkan, potentially with CPU vertex shading;
there is no direct Vulkan Android swapchain presentation in this milestone.
The Thor's second physical display is not implemented or qualified by a stacked
two-view layout. Copies and presentation pacing need later performance work.

D-pad/A and bottom-view touch feed the real HID path. The audible source is
guest-generated PCM through DSP HLE at **32728.498046875 Hz**. Android playback
uses **stateful linear resampling to 48000 Hz**, preserving the rate relationship
instead of labeling guest samples as 48 kHz. Bounded audio queuing records
generation, conversion, writes, playback, partial writes, flushes, drops and
underruns. An audio write/playback counter is not proof that the user heard it.
This tone does not qualify DSP firmware, arbitrary DSP programs, ADPCM/AAC or
complete game audio.

A single session-owner thread performs native open/frame/pause/resume/report/
close. Backgrounding clears held input and pauses guest/audio work; Activity
recreation reattaches to the existing session. Select + Start requests guest exit;
the Android Stop action closes the session and saves its observations. The
automatic suite separately verifies guest DSP shutdown and exit. Failed or
interrupted execution is recorded separately. These are
implemented and locally checked mechanisms awaiting the device checks below, not claims that every
Android lifecycle or provider failure is already qualified.

## Report ownership and device acceptance

<!-- CodexAstraUlt: Retain automated evidence in one bounded latest report and
require actual visible/audible behavior before promotion to private-game boot. -->

Automatic `interactive_probe` evidence and optional manual `interactive_session`
evidence are separate. ProbeController remains the sole writer of
`files/latest-probe.json`. A manual session captures the latest completed run,
reserves a session token, persists an incomplete marker before execution and
merges bounded observations back into that run. Existing CPU/graphics/runtime
and automatic homebrew sections are preserved. Manual work does not upgrade a
failed automatic result. Export uses the exact persisted bytes; a stale callback
must not attach observations to a new run.

The 0.0.6 Thor gate requires **both** passing automatic checks and a manual result:

1. Both guest views are visible and recognizable, with no missing/corrupt image.
2. D-pad/A and bottom-view touch change the actual guest output; release clears
   the held state. Check hardware and on-screen controls separately when available.
3. Guest audio is heard and A changes the tone; record silence, distortion or
   persistent interruption instead of inferring success from PCM counters.
4. Background/resume and view replacement preserve a usable session, clear stale
   held input and recover audio without duplicate execution.
5. Normal session exit completes and the saved latest report retains the automatic
   and manual evidence. Save failed or partial reports too.

Use **Test original homebrew** after the automatic run. The owner can confirm
**I can see both guest screens** and **I heard the guest's tone** only when true;
these are manual observations, separate from frame/audio counters. Finish with
**Stop and save session**, then **Save report** on the probe screen. See
[Android instructions](../ANDROID_PROBE.md#006-manual-thor-test) for the device workflow. An
automatic report alone does not qualify these manual observations. The required
interactive-device gate must pass before **0.0.7 promotion**; a failed check
requires diagnosis and a corrective build.

## Remaining boundaries

<!-- CodexAstraUlt: Keep original-guest progress separate from private games,

This milestone does not load retail games or 3DSX, implement a universal title
launcher, qualify CRO lifetime/concurrent executable changes or establish full
New 3DS scheduling. The passed 0.0.5 memory layouts remain bounded original tests,
not Xenoblade compatibility. Dark Moon, Xenoblade Chronicles 3D and Sonic &
All-Stars Racing Transformed still require separate private exact-revision
baselines. No Dark Moon graphics fix, playable game speed, 2×/4× result, long-run

established by this original homebrew build.
