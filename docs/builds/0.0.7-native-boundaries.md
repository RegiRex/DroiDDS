## Runtime correction

<!-- CodexAstraUlt: Replace dispatch-relative timing and asymmetric deadline
observation with shared guest-cycle scheduling, retaining long native dispatches. -->
Both CPU routes now request scheduling when a kernel deadline becomes due and
before executing the next guest instruction. Periodic preemption advances from
its previous 8192-cycle boundary instead of shifting to the end of a native
dispatch. A lone thread does not create an unnecessary scheduling request.
Elapsed work is accounted before a syscall can make a new thread runnable;
additional HLE cycle charges are accounted afterward as well.

Four of five original scheduler regression cases fail on the prior code. All
six final cases pass, covering a lone thread, sleeping threads, timers, ready
peers, CreateThread and optional boundary markers. A lone native thread still
executes 100,000 guest instructions in one dispatch. This is a dispatch-count
oracle, not a performance benchmark. The interpreter now queries kernel
deadlines per instruction; its added cost with many threads/timers has not been
performance-qualified. A cache would require reliable invalidation of the
currently mutable kernel state.

## What the additional comparison means

<!-- CodexAstraUlt: Preserve arbitrary-cycle mismatches rather than masking
flags whose values are absent from a liveness-optimized budget snapshot. -->
Generation 3 saves only changed locals still needed by a native continuation
when its budget ends. The original comparator retains those raw observations
and their `different` result. It cannot infer semantic divergence merely from an
omitted dead flag, or prove that such omissions are generally harmless.

SVC exits save all changed generated locals before returning to the runtime.
An explicitly enabled, fixed-size marker records completed SVC identity without
an event log. The worker retains at most four full post-SVC samples, using the
first new SVC at or after each 100,000 / 500,000 / 1,000,000 / 2,000,000-cycle
threshold. Thresholds crossed by the same sample are coalesced. No execution
limit is raised to obtain a missing sample.

`synchronized_comparison` requires matching event ordinal, cycle, SVC number,
SVC PC and originating guest thread, plus equal recorded state. Cumulative
dispatch/callback counters at that boundary prove positive generated native
work before a matching sample; native work occurring later cannot qualify it.
Missing samples are explicit. An empty comparison remains `inconclusive`.
Identity/state differences remain `different`. This supplemental result never
rewrites the original raw comparison or qualifies a blocked/failed route.

The observations cover active CPU state, selected scheduler fields, memory/audio
fingerprints and graphics counters. They do not serialize every saved thread or
HLE object. Equal samples are bounded observations, not proof of whole-machine
equivalence, general mutable-code support or successful game boot.
