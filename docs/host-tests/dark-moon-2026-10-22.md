## Owner-reported run-004 scheduler trace

<!-- CodexAstraUlt: Attribute the observed repeating wait to the supplied
trace, without treating a register-pointer hypothesis as a confirmed load. -->
The owner updated to `aadc5fa`, rebuilt offline and ran exactly one diagnostic.
The input hash matches run-003, and a new worker hash is retained locally. The
run exhausted the cycle budget after 0.083960334 seconds of worker time with
the same 433,366 instructions, 2,681,118,560 cycles and 597 frame events as
run-003. GPU and audio activity remained zero.

Trace event #3 is a one-millisecond `SleepThread` at `0x004B23A4`; event #6
resumes at `0x004B23A8` on its deadline with r0-r3 zero. Another sleep follows
13 cycles later. The trace counts 9,999 sleep calls, retains 192 events and
omits 39,804. No pending correlations were dropped or thread snapshots
truncated, and no concrete runtime error was reported.

This points to the guest's polling condition rather than a missed wake deadline.

<!-- CodexAstraUlt: Record the subsequently supplied register evidence without
inferring the intervening load or its offset from a pointer value alone. -->
The owner subsequently supplied the JSON excerpt for event #3. Its `args[4]`
is `536350720` (`0x1FF81000`), so R4 holds the shared-page base at the sleep.
Its PC is `4924324` (`0x004B23A4`), SVC number is 10, and the requested sleep
is 1,000,000 nanoseconds. Entry cycle 303,392 and wake deadline 571,503 differ
by 268,111 cycles, consistent with the one-millisecond timeout conversion.
This supports the shared-page polling lead, but the actual load/branch remains
unobserved. R4 alone does not prove that offset `0x86` is the polled byte.

Source inspection found a separate, concrete initialization omission:
`init_shared_page` never published the readiness byte at offset `0x86`, leaving
guest address `0x1FF81086` zero. The expected initialized value is one, used by
startup readers before querying the running hardware. The generic correction
and original-guest regression are recorded in
[the shared-page readiness change](../builds/0.0.7-shared-page-ready.md).
The owner has now supplied that correction's private result below. Neither this
trace nor that correction alone establishes interactive boot or Thor performance.
