**Draft: build verification and publication are pending. No 0.0.6 Thor result
is claimed.** The [build record](../builds/0.0.6-interactive-homebrew.md) holds the
current gate status.

This build adds an original 3DS program with two visible guest views,
D-pad/A/touch interaction and guest-generated audio. It uses real HID, GSP/PICA
and DSP HLE paths. Automated checks compare interpreter/software,
native/software and native/Vulkan images and PCM, while retaining every 0.0.5
CPU, Vulkan, runtime, memory-layout and code-safety check.

The Android frontend shows 400×240 and 320×240 views together on **one Android
display**. Guest PICA rasterization uses Vulkan; pixels are read back and
presented with Bitmap/Canvas. This does not enable the Thor's second physical
display or direct Vulkan presentation. Guest PCM is resampled from
32728.498046875 Hz to 48000 Hz for Android playback; no DSP firmware is included
or qualified.

When publication is verified, install `DroidDS-0.0.6-android-arm64.apk` and open
**DroidDS Probe**. Complete its automatic checks, then tap **Test original
homebrew** and follow [Android instructions](../ANDROID_PROBE.md#006-manual-thor-test): check both views,
D-pad/A/touch, audible audio, background/resume, view replacement and normal exit.
Confirm the screen/audio checkboxes only when true. Tap **Stop and save session**;
after returning to the probe, use **Save report** and share
`droidds-latest-probe.json`, with any visible/audio problem described. Failed or
partial reports are useful. No game file is needed.

An automatic pass cannot establish that the images were visible or the tone was
heard. The manual Thor gate must pass before the next private-game boot milestone.
This original homebrew does not establish retail-title compatibility, Dark Moon
graphics corrections, playable speed, shader-stutter elimination or sustained
memory stability.

ARM64 Android 10/API 29 or newer is required, plus the renderer's Vulkan 1.3
feature/format contract. Vulkan rasterization and GPU vertex execution are
reported separately; the Thor's 0.0.5 report used CPU vertex shading.

Public diagnostic builds use one-off CI signing certificates. If Android rejects
an update, save any report you need, manually uninstall **DroidDS Probe**, then
install the new APK. This removes that probe's private data; Uberhar is a
separate app. Automation does not uninstall apps to resolve signing conflicts.

The intended four release files are the APK, `BUILD_REPORT.json`, `SHA256SUMS`
and `THIRD_PARTY_NOTICES.txt`. Private games, derived retail code and signing
keys are excluded. Final build and download evidence remain pending until
recorded by the release coordinator.
