DroidDS 0.0.4 expands the foundation checks before full runtime integration:

- **Eight CPU cases:** adds flags/shifts, Thumb-to-ARM transitions, exact finite
  floating-point arithmetic and progress with a tiny instruction budget.
- **Code safety:** rejects stale generated code, changed executable bytes before
  native dispatch, and guest writes into the fixture's executable region.
- **Renderer requirements:** checks the pinned runtime's Vulkan 1.3 features and
  formats, then executes pushed texture/uniform descriptors, depth/stencil and
  depth-clamp draws, plus storage-image compute. Unsupported capabilities are
  named in the saved report.
- **New 3DS audit:** original host fixtures reproduce header decoding and memory
  allocation defects. Their integration fixes are planned for 0.0.5; this APK does
  not claim to fix Xenoblade or run games.

Download **DroidDS-0.0.4-android-arm64.apk**, open **DroidDS Probe**, let the checks
finish, then tap **Save report**. Attach `droidds-latest-probe.json`, including if
checks fail. The report is sufficient; no game file or visual judgment is needed.
The app requires ARM64 Android 10 or newer.

The release checks actual host CPU and software Vulkan execution, with Khronos
and synchronization validation. **The new Thor checks remain pending.** These
are original synthetic fixtures, not PICA translation, gameplay or a speed test.
The CPU code-safety policy is bounded to single-threaded immutable fixture text;
it does not yet qualify CRO loading/unloading or concurrent code changes.

**Installing over an earlier probe:** public diagnostics currently use one-off
CI signing keys. If Android rejects the update, save any report you need, then
manually uninstall only **DroidDS Probe** and install 0.0.4. Uninstalling deletes
that app's private report. Uberhar is a separate package. Automation never
uninstalls to resolve a signature conflict. Stable product signing remains
required before private game packages; private CI keys are never published.

The APK needs no network, broad storage, Google or vendor-service permission.
One bounded private report is retained. The four release files are the APK,
`BUILD_REPORT.json`, `SHA256SUMS` and `THIRD_PARTY_NOTICES.txt`.

The owner's standing instruction is recorded: after validating each report,
continue into the next qualified roadmap build through 0.1.0 without a routine
confirmation round. A failed gate requires a fix before promotion.
