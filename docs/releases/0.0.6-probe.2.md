# DroidDS 0.0.6 — audio pacing and clearer screen testing

<!-- CodexAstraUlt: A corrective public fixture build retains the .6 gate;
the publication workflow must pass before any asset is available. -->

This corrects the Android frontend after the first 0.0.6 Thor report. That
report passes the automatic CPU, Vulkan, runtime and homebrew checks, and the
owner confirms both guest views were visible. It also recorded 197 audio
underruns, no guest-consumed touch and no Activity recreation.

The correction uses accumulated frame deadlines to avoid adding scheduling
delay to every frame, and buffers real guest PCM before starting audio.
It retains all guest execution and draws. Bounded measurements distinguish
timing overruns, touch callbacks inside the image and touch submitted to the
guest. These changes still need a Thor result; they do not establish that
device audio underruns are eliminated.

The two labeled 3DS views remain on **one Android display**. The Thor's
separate lower physical display is not used yet. Landscape puts the controls
beside the views, and **Recreate view** provides a direct lifecycle test.

Install `DroidDS-0.0.6-android-arm64.apk`, open **DroidDS Probe**, and let the
automatic checks finish. Then:

1. Open **Test original homebrew**. Use the D-pad and A; listen for the tone.
2. Hold and drag inside the **colored lower guest image**, then release.
   Check that its marker responds.
3. Tap **Recreate view**, then briefly switch apps and return. Check that
   both views, controls and audio recover.
4. Confirm the two screen/audio checkboxes if correct, then tap
   **Stop and save session** and **Save report**.

Share the report and mention any sound interruption or input problem.
The app identifies itself as **0.0.6 · correction 2**, with Android install
code **7**. It is not the 0.0.7 private-game milestone. No game file is needed.

Public diagnostic builds use one-off CI signing certificates. If Android
rejects the update, first save any report you need, then manually uninstall
**DroidDS Probe** and install this APK. Uninstalling deletes that probe's
private data. Leave Uberhar installed.

The four public assets are the APK, `BUILD_REPORT.json`, `SHA256SUMS` and
`THIRD_PARTY_NOTICES.txt`. The release workflow retains every earlier runtime,
graphics, CPU and package gate. Actual Thor touch, audio and lifecycle
qualification remains separate from build/publication checks.
