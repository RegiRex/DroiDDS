# DroidDS 0.0.5 — integrated runtime diagnostic

This build adds an original 3DS program that runs through the real loader,
system services and PICA graphics path. It compares interpreter/software,
native/software and native/Vulkan execution against exact expected pixels.
The existing eight CPU cases and Vulkan platform tests remain required.

The integration fixes New 3DS header/memory handling, allocation bounds and
rejected-state restoration. It also fixes conditional-branch instruction
accounting in the compiler and Vulkan synchronization/resource-use errors.
Shader compilation jobs and retained translation/pipeline objects now have
explicit admission limits. These are correctness and resource-management
changes; this probe does not measure game performance or prove leak freedom.

Install `DroidDS-0.0.5-android-arm64.apk`, open **DroidDS Probe**, wait for all
results, then use **Save report** and share `droidds-latest-probe.json`.
Failed reports are useful too. No game file is needed for these checks.

This diagnostic has no visible 3DS display, game picker, controls or audio yet.
The original program renders offscreen. Real game boot, broader CPU/module
behavior, sustained memory, and Thor execution of the new runtime remain separate
qualification gates. The next public milestone targets visible interactive
homebrew on Android; private game baselines remain open until local inputs exist.

ARM64 Android 10/API 29 or newer is required; passing the graphics gate also
requires the runtime's Vulkan 1.3 feature/format contract. The renderer reports
whether vertex shading uses CPU or GPU separately from Vulkan rasterization.
Static graphics state is supported, but first-use pipeline compilation can still
stall; this release does not establish shader-stutter elimination.

Public probes use one-off CI signing certificates. If Android rejects an update,
save any report you need, manually uninstall **DroidDS Probe**, and install this
APK. That removes this probe's private data. Uberhar is a separate app.

The four release files are the APK, `BUILD_REPORT.json`, `SHA256SUMS`, and
`THIRD_PARTY_NOTICES.txt`. No private title inputs, derived retail code or signing
keys are included. Host correctness and package checks are separate from the
owner's next Thor result.
