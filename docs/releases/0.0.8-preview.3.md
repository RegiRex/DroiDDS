# DroiDDS 0.0.8 preview 3 — vertex output and pipeline diagnosis

<!-- CodexAstraUlt: Describe the candidate's concrete CPU correction and

The code 12 Thor test reaches Dark Moon's file-selection menu with CPU vertex
shaders, but remains slow and crackling. CPU vertex processing consumes about
one-third of core time. The GPU trial fails while creating a Vulkan pipeline
before any GPU-vertex workload is submitted.

This candidate targets two concrete issues:

- Map CPU shader batches directly into smaller packed vertices, replacing the
  draw/chunk-sized full-register vector with bounded scratch while preserving
  behavior/order and the existing full-output geometry path.
- Retain bounded metadata identifying the actual failed pipeline's stage,
  module, static/specialization state, Vulkan result and attempt context.

Automatic remains the default. Native guest execution and vertex-shader location
remain separate choices. No private shader dump, continuous logging, new monitor,
draw skipping or optional CPU shader-JIT enablement is part of this update.
The existing preparation, title libraries and owner signer remain reusable.
