# DroiDDS 0.0.8 preview 1 — audio delivery and timing

The owner has reached Dark Moon's interactive title and file-selection menus on
the Thor in Native mode, with A-button response and normal stop without reported
runtime faults. This achieves the central 0.0.7 boot objective. **0.0.8-preview.1**
starts the next development stage: improving audio delivery and measuring the
work that still prevents a playable segment.

The two private reports recorded **1,361 and 2,889 audio underruns**, alongside
crackling and slow visible progression. They advance 21.255 and 34.140 guest
seconds in 100.010 and 201.650 seconds of core work, with zero reported PCM
drops and all converted samples written. Slow sample production is established;
whole-session active speed and the dominant processing phase need the added
timing measurements. The queue correction addresses a separate reproduced bug.

## Candidate changes

<!-- CodexAstraUlt: Describe targeted frontend changes and bounded diagnostics;
preserve actual guest work and avoid claiming that buffering fixes slow emulation. -->
- Drain queued PCM into available platform capacity before adding new samples,
  avoiding drops caused solely by the old enqueue-before-drain ordering.
- Stop and capture audio at the explicit session end before native resource
  teardown, so shutdown work does not extend the measured playback interval.
- Record bounded active-time, execution, audio-submission, queue and pacing
  aggregates. These distinguish sample-production limits from delivery delays
  without adding continuous logs or a new monitoring thread.
- Separate command-processing and screen-readback host time, and identify the
  installed frontend version in the exported report.

These changes do not enlarge the audio buffer, fabricate PCM, drop guest work,
time-stretch sound or promise that slow emulation becomes real-time. The prior
underrun count is not retroactively explained away as shutdown noise.
