# DroidDS 0.0.4 runtime probe: owner-supplied Thor result

<!-- CodexAstraUlt: Record the expanded device gate without publishing private
run identifiers or mistaking original backend fixtures for the game runtime. -->

Evidence reviewed **2026-10-19** (America/New_York). The owner supplied
`droidds-latest-probe.json` from DroidDS Probe **0.0.4 / code 4**. The strict
`tools/run_android_probe.py::validate_report` contract accepts the report: all
eight CPU fixtures, both CPU corruption controls, all three immutable-code
safety controls, the baseline Vulkan tests and the expanded renderer-operation
tests pass. The raw report remains outside Git, including its request/run UUIDs,
process ID and device timestamps.

This completes the bounded Thor execution gate for
[the 0.0.4 probe](../builds/0.0.4-runtime-probe.md). It supports proceeding to
runtime integration in 0.0.5; it does not establish PICA emulation, game
compatibility or playable speed.

## Vulkan output and capability results

<!-- CodexAstraUlt: Separate baseline and renderer counters, and record the
missing optional dynamic state so integration exercises the static path. -->

The baseline 16 × 16 RGBA8 test completes **three resource cycles**, **three
pipeline creations** and **twelve draws**. Each of `solid_red`, `solid_green`
and `split_red_green` completes three cycles and compares 768 pixels, for
**nine readbacks / 2,304 pixels**, with **zero mismatches**. All **nine** injected
pixel-mutation controls are rejected.

The renderer-operation probe identifies contract **`zakuro-412900a`** and reports
all ten required capabilities available: Vulkan 1.3, a shared graphics/compute
queue, push descriptors, depth clamp, D24S8 attachment support, RGBA8
color/sample/transfer support, dynamic rendering, synchronization2,
pipeline-creation cache control and the required push-descriptor limit.
`missing_required` is empty.

The expanded probe creates **two pipelines**, completes **two image readbacks /
512 pixels**, and passes all **three** mutation controls. Both graphics sections
report no execution error. These are original Vulkan operations representative
of backend needs; they are not execution of the actual PICA renderer or a game.

| Optional capability | Reported support |
| --- | --- |
| Logic operations | `true` |
| Pipeline statistics queries | `true` |
| Dynamic blend state | **`false`** |
| Dynamic logic-operation state | **`false`** |

The missing optional dynamic states do not fail this contract. The integrated
renderer must select and test the **static pipeline-state path** on this Thor
driver. It must not assume that Vulkan 1.3 implies these optional states, invoke
unavailable dynamic-state commands, or omit blend/logic-operation behavior.
The probe does not establish correct handling of all such PICA states; that is
a specific integration gate for 0.0.5.

The Android build does not enable the Khronos validation layer. Correct device
readbacks and separate host validation runs are distinct evidence; this report
is not an Android validation-layer pass. Three short resource cycles do not
demonstrate sustained leak freedom.

## Validation boundary and reproduction

<!-- CodexAstraUlt: Validate the owner's upload against a fixed version while
reserving external-request and installed-package binding for a fresh ADB run. -->

The actual check used the current strict validator at repository commit
`7d0d0052fa6f5bfd19f8e93d169dcae6c34bc0ef`, required version **0.0.4 / code 4**,
checked the report-size bound and reused the request identifier already in the
upload. It passed without changing the validator. To reproduce from that
checkout with the private report outside Git:

```bash
# CodexAstraUlt: Validate internal consistency without printing private identifiers.
PROBE_REPORT=/absolute/private/path/droidds-latest-probe.json python3 - <<'PY'
import json
import os
import sys
from pathlib import Path

sys.path.insert(0, "tools")
from run_android_probe import MAX_REPORT_BYTES, validate_report

path = Path(os.environ["PROBE_REPORT"])
assert path.stat().st_size <= MAX_REPORT_BYTES
report = json.loads(path.read_text())
validate_report(report, report["android_shell"]["request_id"],
                {"version_code": 4, "version_name": "0.0.4"})
print("Uploaded 0.0.4 report is internally consistent and passes all probe gates")
PY
```

This manual-upload check does **not** bind the report to a newly issued external
request or independently inspect an installed APK, its hash, signature or source
commit. Device and application metadata are self-reported. The existing ADB
runner supplies request and installed-APK-hash binding for a new local run.
The JSON does not identify its export method or establish picker cancellation,
rotation or provider-error handling.

The reported monotonic duration is **30 ms for the whole diagnostic run**. It is
not a frame-time, gameplay or sustained-performance benchmark, and it does not
show a performance gain over the 31 ms reported by 0.0.3's different workload.
