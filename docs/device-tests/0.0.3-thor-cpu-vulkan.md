Evidence reviewed **2026-10-19** (America/New_York). The owner supplied
`droidds-latest-probe.json` from DroidDS Probe 0.0.3. The existing
`tools/run_android_probe.py::validate_report` accepts the uploaded report against

device timestamps.

This extends the [0.0.2 CPU result](0.0.2-thor-cpu.md) with reported execution of
the original offscreen Vulkan fixture on the Thor. It is separate from the
previous host software-Vulkan and APK build evidence.

That is **nine readbacks and 2,304 exact pixel comparisons, with zero
mismatches**. All nine deliberate readback-byte mutations are rejected, proving
that the comparator detects the injected errors. The combined report has no
Vulkan execution error and reports both CPU and graphics as passed.

The Android build does not enable the Khronos validation layer, so its recorded
`validation_layer_enabled: false` is expected. Correct pixel output is device
evidence; the separate host run with Khronos and synchronization validation
provides a different check. This Android report must not be described as an
Android validation-layer pass.

## Validation boundary and reproduction

<!-- CodexAstraUlt: Reuse the upload's nonce only for consistency validation;
reserve fresh-request and installed-package claims for an actual ADB run. -->

Validation uses the expected 0.0.3 version fields and the request identifier
already in the uploaded report. It checks structure, declared platform and
version agreement, exact execution counters, CPU results, graphics readbacks and
negative controls. It does **not** bind the upload to a newly issued external
request, independently inspect the installed APK, or verify that APK's hash,
signature or source commit. Device and app metadata are self-reported.

To reproduce this consistency check, run from the repository root with a private
copy outside the checkout:

```bash
# CodexAstraUlt: Keep the private report external and require the reviewed version.
PROBE_REPORT=/absolute/private/path/droidds-latest-probe.json python3 - <<'PY'
import json
import os
import sys
from pathlib import Path

sys.path.insert(0, "tools")
from run_android_probe import validate_report

report = json.loads(Path(os.environ["PROBE_REPORT"]).read_text())
validate_report(report, report["android_shell"]["request_id"],
                {"version_code": 3, "version_name": "0.0.3"})
print("Uploaded 0.0.3 report is internally consistent and passes CPU/Vulkan gates")
PY
```

Use the validator from tag `v0.0.3-probe.1` to reproduce this version's contract;
future versions may change the accepted fields. The existing ADB runner adds
external-request and installed-APK-hash binding for a new local device run.

The JSON does not record how it was exported. Receipt of the file establishes
neither use of **Save report** nor coverage of that action's cancellation,
rotation or provider-error behavior.

The reported monotonic elapsed duration is **31 ms for the whole diagnostic
run**. It is not a gameplay, frame-time or sustained-performance benchmark.
Three resource cycles do not demonstrate sustained leak freedom. The report
does not qualify a 16 KiB-page host, presentation surfaces, the generic PICA
pipeline, Android lifecycle recovery, New 3DS guest behavior or any game.
