## Intro workload and CPU cost breakdown

<!-- CodexAstraUlt: Keep nested command timings disjoint and preserve the intro's
large interpreted-instruction count without inventing an expensive code region. -->
The owner intro executed **8,844,758,769 cycles / 32.989062 guest seconds** during
**197.999015 worker seconds**. It delivered **1,957 frame events/images** and
executed **3,287,060,427 native instructions**, **47,435,035 interpreted
instructions** and **53,649,900 runtime step dispatches**. These last two counts
are not interchangeable: a dispatch is a call to the core step function, which
may run a native block, an interpreted instruction or scheduling/idle work.
Neither count measures host time. Both code 14 reports have zero
callback-interpreted instructions. The report does not identify which guest
regions account for the intro's interpreted work, so it cannot establish a CRO
or particular game routine as its cause.

| **Total core slices** | **100.000786 s** | **100%** | **194.825630 s** | **100%** |

The first four rows partition command time: **58.268575 seconds** in the menu
and **125.896471 seconds** in the intro. Shader/decode/placement are disjoint
subsets, not extra time to add to their command parent. These are elapsed wall
scopes, not hardware utilization. Shader time includes CPU shader execution,
output mapping/packing and worker joins. Decode includes index expansion,
deduplication and attribute decoding, but excludes the initial raw-index read
and cached input-plan lookup. Placement includes assembly, clipping, culling and
screen placement before Vulkan draw work. The remainder is subtraction, not a
separately instrumented subsystem. Code 13 did not measure decode or placement.

Both code 14 runs record zero geometry-mode selections. Menu parallel-threshold
selections are **36,762 / 634,729 CPU batches (5.79%)**; intro selections are
**153,901 / 837,186 (18.38%)**. These count batches meeting the vertex-input
threshold, not active worker counts or completed geometry-stage invocations.
The intro has **434,677,337 CPU vertex inputs** and **876,813,285 vertex
references**. Its different scene and input sequence prevent a controlled
performance comparison with the menu.

The **3,558 menu / 164,486 intro** difference between CPU batches and recorded
draws is not evidence by itself that required draws were skipped. Source
inspection at `a09289a` distinguishes the counters:
[CPU processing and placement](../../vendor/zakuro/crates/zakuro-gpu/src/raster.rs)
precede [hardware drawing](../../vendor/zakuro/crates/zakuro-gpu/src/raster/hardware.rs).
`draw_inner` returns successfully for empty indices or empty clipped scissor;
placement can remove triangles through clipping/culling. `recorded_draws`
increments when `record` emits a Vulkan draw, and can also include twin draws.
The JSON does not count individual early-return reasons or cull outcomes, so it
cannot assign the observed difference to one cause or validate every decision.
The owner's no-glitch observation remains separate visual evidence.

Both sessions have zero GPU-vertex draws, software raster fallbacks, draw/compiler
errors and resource-limit events. All three pipeline-failure slots are null.
Runtime errors, first blocker and diagnostic fault are null; fatal errors,
prefetch aborts, unsupported services/SVCs and sampled memory-fault pages are
zero. Final observed PC is `0x0011894C`; it identifies the observed endpoint,
not an expensive or faulty instruction. The outer reports are stopped; nested
running snapshots precede closure. **64 MiB guest application allocation** is
not process/driver memory and does not establish the presence or absence of a
memory leak.
