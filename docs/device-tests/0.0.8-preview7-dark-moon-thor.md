## Implication for the native direction

<!-- CodexAstraUlt: Relate native progress to measured graphics cost without
equating instruction fractions to elapsed CPU time or promising an upper-bound gain. -->
Code 17 already records **99.989957% of counted guest instructions on the
native route**, with zero callback-interpreted instructions. That fraction is
not a time measurement and does not imply that all emulated hardware is native.
The disjoint PICA-command, queued-display, queued-texture and scanout scopes sum
to **93.408404 s, or 93.32% of core time**. CPU vertex shading alone uses
30.392867 s (**30.37% of core**); it is nested inside PICA work.
Hardware-transfer attempts plus texture synchronization use 29.886023 s
(**29.86% of core**), within those graphics scopes.

The remaining **5.909062 s** of core time includes guest execution, scheduling,
guards and memory synchronization. It is not measured native execution alone.
Consequently, this run supports investigating graphics translation and
synchronization as architectural targets; changing APK packaging or optimizing
only native dispatch would not address the dominant measured scopes. A future
design could change the workload itself, so these partitions are not a universal
speed ceiling or proof that any proposed renderer will be faster.
