vertex/geometry execution, packing and worker joins; it excludes attribute
decoding, clipping and Vulkan work. These broad scopes identify optimization
targets but do not identify the exact expensive function or instruction.

Speed is descriptively **0.398 percentage points** higher, but code 13 also
executed more guest work, including 3.22% more counted vertex inputs and 3.47%
more draw calls. Cost per counted vertex input was about **0.98% higher**.
These single runs do not isolate packing changes from different scene exposure,
shader work or thermal/system variance; neither a gain nor regression is
established. The reports do not distinguish packed versus full-width geometry
output. Mean inputs per batch are 310.23/309.50, but no batch-size distribution
is recorded, so this cannot establish how many batches ran in parallel.
Inputs are deduplicated within indexed draws, not unique across the session;
frame events are not unique game FPS, and instruction share is not host-time
share.

CPU reports zero GPU-vertex draws, zero software raster fallback, no runtime
blocker and no renderer/resource-limit errors. All three pipeline-failure slots
are null. The 64 MiB memory value is guest application allocation, not measured
process or driver memory and not evidence of the presence or absence of a leak.

## GPU failure retained for later work

<!-- CodexAstraUlt: Identify the attempted public shader modules without
claiming the vertex shader itself is faulty or asking for another GPU trial. -->
The single GPU launch showed black output, then an error by **12.342 wall
seconds after Play**, including startup. Worker execution was **2.143061
seconds**. No sound was heard and no failed launch was repeated. A separate
preflight stopped before Play and performed no guest execution.

The first foreground pipeline failure records Vulkan result **-13** with the
**interpreted GPU vertex module**, generic fragment mode and rasterized depth:

| Attempted module | Bytes | Diagnostic FNV-1a64 |
| --- | ---: | --- |
| Public `shade.vert.spv` | 50,320 | `245d2186970be2f0` |
| Public `raster.frag.spv` | 96,856 | `8431ed93c93708e0` |

These identities match the [code 13 cloud build](../builds/0.0.8-pipeline-followup.md).
The static blend value is `0x76760000`, color format 37 and color mask 7;
there is no depth attachment, depth format and creation flags are zero, logic
operation is null, and the 30 fragment-specialization values are 29 zeroes
followed by 1. Background and cache-probe failure slots are null.

The attempted vertex stage is now known; it does not identify which shader,
linkage or pipeline/device condition caused the rejection. It also does not
mean the guest CPU used Interpreter execution. FNV is a diagnostic fingerprint,
not a cryptographic hash. Driver shader-link/compilation messages do not isolate
application versus driver responsibility. Retaining one translated module does
not identify that module as the failed attempt.

The runtime stops with `title_renderer_draw_failed` / `renderer_draw_failed` at
cycle **378,491,483**, observed PC **`0x0011894C`**. That PC is where the failure
was observed, not an identified faulty guest instruction. The outer completed
slice counter is **378,484,328**; the 7,155-cycle failed-call tail remains
separate. There are two draw errors, **zero GPU-vertex draws and zero Vulkan
submissions**, with one placed draw recorded. Zero compiler failures and two
outstanding compiler jobs describe a different path and do not negate the
foreground Vulkan failure. All 44,320 PCM frames are silent; four underruns
in this short prefix provide no audio-quality comparison.

Further Thor GPU tests are deferred. Preserve this bounded evidence for a
later isolated pipeline investigation. The current CPU priority does not close
the GPU defect, qualify sustained gameplay/save-load/audio, or establish the
0.1.0 limited-beta milestone. No unchanged local rerun is needed to recover
already supplied measurements.
