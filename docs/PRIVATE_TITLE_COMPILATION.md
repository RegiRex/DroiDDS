## Resource policy and resume

<!-- CodexAstraUlt: Avoid automatic per-core compilation and preserve expensive
completed work without treating partial objects as valid native output. -->
Compilation runs **one compiler command at a time**, largest C source first.
It preserves `-O2`, `-ffp-contract=off` and `-fno-math-errno`; GCC retains its
existing garbage-collection flags. The copied C/headers are read-only. A small
additional C unit exports the exact preparation and compilation contract hashes.
The installed system headers and runtime libraries remain part of the host
toolchain; this is not a fully hermetic toolchain or binary provenance attestation.

Default limits are:

| Limit | Default |
| --- | --- |
| Compiler/linker batch deadline | 1800 wall seconds |
| Each compiler/linker command | 300 wall seconds |
| CPU per process, including its threads | 260 seconds |
| Virtual address space per process | 4096 MiB |
| Individual object/compiler temporary file | 128 MiB |
| Individual linker output/temporary file | 512 MiB |
| Retained build-directory allowance | 4096 MiB |
| Retained log tail per command | 64 KiB |

Allow at least 4 GiB free for the new build directory. Only generated C/headers
are copied; the game snapshot is verified in its preparation directory and is
not copied again. The retained build allowance covers the source copy, objects,
library, attempt files and reports. It is checked between commands, with metadata
space reserved before success publication; it is not an OS aggregate disk quota.
Compiler subprocesses have hard per-file limits. Failed partial files remain
available, and diagnostic reporting can outlive a failed storage allowance.

Each compiler helper inherits CPU/address-space limits separately; CPU is not
summed across the process tree. The wall deadline supervises the compiler process
group. Bounded input verification, auditing and report publication can extend
elapsed time beyond the compiler batch deadline. An observed signal is reported
as a signal; it is not automatically labeled an out-of-memory failure.

Each completed object receives an atomic receipt binding its source, headers,
preparation, compiler/helpers, recipe and object bytes. An interrupted object has
no receipt and cannot be reused. A later explicit `--resume` against the same
output verifies all retained identities and compiles only missing objects.
Previous attempts and reports remain intact; a lock prevents two coordinators
from using that output simultaneously. A changed recipe, source, compiler or
object rejects reuse. A completed build is revalidated without relinking.

For an initial compilation, run **one batch** and stop at completion,
the first rejection/failed command, or the batch deadline. Do not raise limits,
change optimization, skip a source, or automatically repeat a failed command.
